01

Java 语言基础

1–2 周

掌握基本语法、静态类型系统、控制流和常用数据结构，能读懂别人写的 Java 代码。

类比：把它当成"语法更严格的 TypeScript"——变量必须声明类型（或用 var 局部推断），函数叫方法，数组之外还有更强类型的集合。
变量与基本类型条件 / 循环数组 / String 方法 method异常 try/catch泛型 <T>
◎核心概念
  • 八种基本类型 int/long/double/boolean 与包装类 Integer
  • 值传递 vs 引用传递，与 JS 的对象引用不完全一致
  • == 比较引用、.equals() 比较内容
  • 受检异常与运行时异常的区别
  • 字符串常量池、StringBuilder 拼接性能差异
▶动手任务
  • 写一个命令行猜数字游戏
  • 实现斐波那契数列（递归 + 迭代两版）
  • 读取一个 CSV 文件并统计词频
  • 用 try-with-resources 处理文件流
!常见坑
  • 用 == 比字符串——永远用 equals
  • 整数除法 3/2 = 1，忘了转 double
  • 把 null 当空字符串处理，触发 NPE
📚推荐资源

  • 官方教程 Oracle Java Tutorials（Language Basics）

类比：Java 的 interface 类似 TS 的 interface；class 继承类似 ES6 class extends；List<User> 就是强类型版的数组，Map<String, User> 就是强类型版的对象/Object。
class / interfaceextends / implementsList / Map / Set Stream APILambda 表达式
◎核心概念
  • 封装 / 继承 / 多态三大特性，抽象类 vs 接口
  • final、static、abstract 修饰符含义
  • ArrayList vs LinkedList、HashMap vs TreeMap
  • Stream 的 filter/map/reduce/collect
  • Java 8+ 的 Optional 处理空值
▶动手任务

04

Spring 核心：IoC 与依赖注入

1 周

理解 Spring 的核心思想——对象不再自己 new 依赖，而是交给容器统一管理和注入。

类比：这是最反直觉但最重要的一步。可以类比 Vue3 的 provide/inject：你不在组件里手动创建服务实例，而是声明"我需要什么"，由外部容器负责"给你什么"。@Autowired 约等于 inject('someService')。
IoC 容器@Component@AutowiredBean 生命周期@Configuration
◎核心概念
  • Bean 的作用域：singleton（默认） vs prototype
  • 四种注入方式：字段 / setter / 构造器 / 方法参数（推荐构造器注入）
  • @Component / @Service / @Repository / @Controller 语义区别
  • @Qualifier 处理同类型多个 Bean
  • Bean 生命周期：实例化 → 属性注入 → 初始化 → 销毁
  • AOP 与切面：@Aspect 处理横切关注点
▶动手任务
  • 写两个实现同一接口的 MessageService，用 @Qualifier 选择
  • 用 @Aspect 实现方法执行耗时的统一日志
  • 写一个自定义 @Configuration，注册第三方库的 Bean
  • 观察 @PostConstruct/@PreDestroy 触发时机
!常见坑
  • 循环依赖——构造器注入会直接报错，字段注入会隐式跳过
  • 忘了加 @ComponentScan 或包路径不对，Bean 找不到
  • 把 Bean 当无状态用，却在里面存了实例变量
📚推荐资源
  • Spring 官方 Reference - Core 章节
  • 《Spring 实战》第 6 版第 1–3 章
  • B 站：黑马程序员 Spring 精讲（挑核心 IoC/AOP 章节）
阶段验收：能画出一个请求进来后 Bean 之间的调用链路，并解释"为什么要用构造器注入而不是字段注入"。
05

Spring Boot Web 开发

1–2 周

能写出接收请求、返回 JSON 的 REST 接口，理解请求生命周期。

类比：@RestController + @GetMapping 就是后端版的路由定义，类似你在 Express/Nest 里写 router.get('/users', handler)；@RequestBody 自动把 JSON 反序列化成对象，类似前端 JSON.parse 但更强类型。
@RestController@GetMapping/@PostMapping@RequestBody/@PathVariable 全局异常处理application.yml 配置
◎核心概念
  • 请求生命周期：Filter → DispatcherServlet → Interceptor → Controller
  • 参数绑定：@PathVariable / @RequestParam / @RequestBody
  • 参数校验：@Valid + @NotNull/@Size（JSR-303）
  • @ControllerAdvice + @ExceptionHandler 全局异常
  • Jackson 序列化：@JsonFormat / @JsonIgnore
  • Profiles 多环境配置 application-{dev,prod}.yml
  • 跨域 CORS 与 @CrossOrigin
▶动手任务
  • 实现一个 /api/users 的 CRUD（先用内存 List 存）
  • 加参数校验：手机号格式、必填字段、字段长度
  • 写统一响应体 Result<T>{code, msg, data}
  • 用 Postman 测完所有接口，写一个 Collection
  • 接入 Swagger/Springdoc，浏览器打开 API 文档
!常见坑
  • 忘了 @RequestBody，POST 参数一直是 null
  • 日期时区问题：前端传字符串、后端反序列化成 UTC
  • 返回 Entity 直接暴露数据库字段，忘了做 DTO 转换
  • 异常没被捕获，用户看到 500 + 完整堆栈
📚推荐资源
  • Spring Guides: "Building a RESTful Web Service"
  • Baeldung Spring Boot 系列
  • 《Spring Boot 实战》第 4 版
阶段验收：能独立设计并实现 5+ 个 REST 接口，前端用 axios 联调没有奇怪报错，接口文档能一键生成。

数据持久层：Spring Data JPA

1 周

连接数据库，完成实体映射与基本的增删改查。

类比：JPA 相当于 Java 世界的 ORM，作用类似前端项目里连接后端 API 用的 Prisma / TypeORM：定义一个 Entity 类，框架自动帮你生成 SQL，JpaRepository 提供的 findById 之类方法不用你手写。
@EntityJpaRepository@OneToMany 关联事务 @Transactional
◎核心概念
  • Entity 映射：@Table / @Column / @Id / @GeneratedValue
  • 关联关系：@OneToMany / @ManyToOne / @ManyToMany
  • 方法命名查询：findByNameAndStatus
  • 自定义 JPQL：@Query("select u from User u where ...")
  • 分页与排序：Pageable / Sort
  • 事务传播行为：REQUIRED / REQUIRES_NEW
  • 可选：MyBatis-Plus 作为对比（国内更流行）
▶动手任务
  • 把上一阶段的内存 CRUD 换成 MySQL 存储
  • 建立 User / Order 一对多关系并查询
  • 实现分页接口 ?page=0&size=10&sort=createdAt,desc
  • 写一个转账场景，理解事务回滚
!常见坑
  • N+1 查询：循环里挨个访问关联对象，SQL 爆炸
  • 懒加载 LazyInitializationException——Session 已关
  • 没加 @Transactional 或方法非 public，事务不生效
  • 用 ddl-auto=update 上生产，字段被自动改
📚推荐资源
  • Spring Data JPA 官方 Reference
  • Vlad Mihalcea 博客（JPA/Hibernate 权威）
  • 《高性能 MySQL》前 3 章补数据库基础
阶段验收：本地起 MySQL + Spring Boot，接口能对真实数据库读写，日志里看得到 SQL，理解事务边界。

测试：JUnit + Mockito

3–4 天

为接口和核心逻辑补上单元测试与集成测试。

类比：JUnit ≈ Jest/Vitest 的角色，@Test 标注测试方法，断言写法类似 expect().toBe()；Mockito 用来 mock 依赖，类似前端 mock API 请求。
@TestassertEquals@Mock / @MockBeanMockMvc 接口测试
◎核心概念
  • JUnit 5 生命周期：@BeforeEach / @AfterEach
  • 断言库 AssertJ：assertThat(x).isEqualTo(y) 更直观
  • Mockito：when(...).thenReturn(...)、verify(...)
  • @SpringBootTest 集成测试 vs 纯单元测试
  • MockMvc 模拟 HTTP 请求测 Controller
  • Testcontainers 拉起真实 MySQL 做集成测试
▶动手任务
  • 为 Service 层写 3+ 个单元测试，覆盖正常/异常路径

  • Mockito 用在 final 类上失败（需要额外配置）

Cheatsheet
Spring 常用注解速查
写 Spring Boot 时 80% 场景会碰到的注解，按用途分组。看到不认识的，先来这里对一眼。

Bean 声明 & 注入

@Component通用组件，被 Spring 扫描并注册为 Bean
@Service语义化：业务层组件
@Repository语义化：数据访问层，附带 SQL 异常转换
@Controller语义化：MVC 控制器（返回视图）
@RestController@Controller + @ResponseBody，返回 JSON
@Configuration配置类，里面的 @Bean 方法会被注册
@Bean方法级：把返回值注册成 Bean
@Autowired按类型注入依赖（推荐构造器注入）
@Qualifier同类型多 Bean 时按名字指定
@Value注入配置项：@Value("${app.name}")

Web · 路由 & 参数

@RequestMapping通用路由，可指定 method/path
@GetMappingGET 请求映射
@PostMappingPOST 请求映射（Put/Delete/Patch 同理）
@PathVariableURL 路径参数 /users/{id}
@RequestParamQuery 参数 ?name=xxx
@RequestBodyBody 反序列化成对象（JSON → POJO）
@RequestHeader读取请求头
@CookieValue读取 Cookie
@Valid触发 JSR-303 参数校验
@CrossOrigin开启 CORS

数据 · JPA

@Entity标记为实体类，对应数据库表
@Table(name)指定表名（不写就用类名小写）
@Id主键字段
@GeneratedValue主键生成策略（自增/UUID）
@Column列映射，可指定长度、非空

Bad vs Good
前端转 Java 最容易踩的 4 个坑
这些不是语法错误，而是"写得动，但会在生产环境暴雷"的隐患。左边红色是常见写法，右边绿色是推荐写法。
!字段注入 vs 构造器注入
@Service public class UserService { @Autowired private OrderRepository orderRepo; // ← 隐式依赖 }
× 依赖不透明，单测难 mock，可能循环依赖
@Service public class UserService { private final OrderRepository orderRepo; public UserService(OrderRepository orderRepo) { this.orderRepo = orderRepo; // ← final + 构造器 } }
✓ 依赖清晰、可 final、Spring 4.3+ 可省 @Autowired
Lombok 用户可以直接 @RequiredArgsConstructor 让编译器自动生成构造器，代码更简洁。
!直接返回 Entity vs DTO
@GetMapping("/users/{id}") public User getUser(@PathVariable Long id) { return userRepo.findById(id).orElseThrow(); // ← 暴露 password、内部字段、懒加载对象 }
× 数据库字段泄露、序列化 Session 关闭异常
@GetMapping("/users/{id}") public UserDTO getUser(@PathVariable Long id) { return userService.findById(id); // ← DTO }
✓ DTO/VO 隔离层，API 契约与表结构解耦
推荐用 MapStruct 或手写转换。修改表结构时不会影响 API 消费者。
!循环里查数据库（N+1）
List<Order> orders = orderRepo.findAll(); for (Order o : orders) { User u = userRepo.findById(o.getUserId()).get(); // ← 100 条订单会打 101 次 SQL }
× 请求变慢，数据库连接爆
List<Order> orders = orderRepo.findAll(); Set<Long> ids = orders.stream() .map(Order::getUserId).collect(toSet()); Map<Long, User> userMap = userRepo.findAllById(ids) .stream().collect(toMap(User::getId, u -> u)); // ← 一次 IN 查询，内存 join
✓ 批量查询 + 内存 join，2 次 SQL 搞定
JPA 关联查询可用 @EntityGraph 或 fetch join 一次拉齐。
!异常吞掉 vs 交给全局处理
try { return doWork(); } catch (Exception e) { return null; // ← 静默吞异常 }
× 出问题查不到堆栈，用户看到空数据一脸问号
// Service 层直接抛业务异常 throw new BizException("USER_NOT_FOUND"); // 一处统一处理 @ControllerAdvice public class GlobalExceptionHandler { @ExceptionHandler(BizException.class) public Result<?> handle(BizException e) { ... } }
✓ 抛 + 统一转响应，日志与响应格式一致
前端 axios 拦截器只需判断 code !== 0 就能弹提示，链路清晰。
FAQ
前端同学最常问的 8 个问题
选 JDK 8、17 还是 21？
2026 年新项目直接上 21 LTS；面试/进老项目至少要能看懂 8 的写法（大量遗留代码）。差别主要在语言特性：var、record、Sealed Class、虚拟线程（Loom）都是 8 没有的。
Spring 和 Spring Boot 是什么关系？
Spring 是一个庞大的框架家族（IoC、MVC、Data、Security…）。Spring Boot 是它的"脚手架 + 约定优于配置"层，帮你自动装配 + 内嵌 Tomcat + 起飞就能跑。今天学 Spring 就等于学 Spring Boot，不用管早年 XML 配置那一套。
Maven 和 Gradle 学哪个？
先学 Maven：企业占比更高、配置更死板但直观。Gradle 更灵活（用 Groovy/Kotlin DSL），Android 项目和一些新项目会用，等有需要再看。两者能读懂一个就能读懂另一个。
JPA 还是 MyBatis？
国外/中小项目 JPA 更普及，写法接近前端 ORM；国内互联网大厂 MyBatis / MyBatis-Plus 更主流，因为 SQL 可控性更强。作为入门选 JPA（心智负担小），进公司再学 MyBatis 也很快。
没有 hot reload，改代码要重启很痛苦？
加 spring-boot-devtools 依赖 + IDEA 开启"自动构建"，改完 Controller 保存后 1–2 秒热重启。改类结构/依赖关系仍需完整重启，这是 JVM 限制。或者用商业方案 JRebel。
为什么大家都用 Lombok？
Java 写 POJO 需要大量样板代码（getter/setter/构造器/equals/hashCode）。Lombok 用 @Data / @Getter / @Builder 等注解在编译期自动生成，源码干净。缺点是 IDE 需要装插件、调试栈里看不到真实字节码。
Spring 项目怎么调试？
IDEA 里直接点绿色🐞图标就是 Debug 模式，打断点跟前端一样。远程调试：启动加 -agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=5005，IDEA "Remote JVM Debug" 附加即可。
后端要不要学到多线程 / JVM 调优？
入门阶段（这份路线图内）不需要。等你能独立写完 CRUD 项目、能读懂 Spring 官方文档，再深入 volatile / synchronized / ThreadPoolExecutor / GC 这些主题。过早学容易劝退。
Advice
给前端背景学习者的四条建议
01

不要跳过静态类型的"啰嗦"

前期会觉得 Java 写起来比 JS 慢，这是正常的——类型系统在编译期帮你挡掉了大量运行时才会暴露的 bug，是用"啰嗦"换"安全"。

02

IoC/DI 是最大的思维门槛，多花时间

这是和前端组件化思维差异最大的部分，建议动手写 3-5 个小 Demo，观察 Bean 是如何被注入的，理解透了后面 Spring 全家桶都会顺很多。

03

用你熟悉的方式验证接口

后端写好的接口，继续用 Postman/Apifox 甚至你熟悉的 axios 脚本去调用验证，这块经验完全可以复用，不用重新学。

04

尽早做一个前后端联调的小项目

比如用 Vue3 写前端、Spring Boot 写后端的一个 Todo List，联调过程会把零散知识点串成一条完整链路，比单独刷教程有效得多。

建议按阶段顺序推进，每个阶段结束后写一个可运行的小 Demo 再进入下一阶段。
