1什么是 PF

PF (Packet Filter) 是 macOS 从 10.7 (Lion) 起内建的底层包过滤防火墙,继承自 OpenBSD。它工作在网络层,可以基于 IP、端口、协议、接口、方向等对进出流量做精细化控制。

前端类比 如果说 macOS 系统偏好设置里的“防火墙”开关像 Vue3 的模板语法 —— 简单、面向使用者;那么 PF 就是底层的 render 函数:能力更强、更灵活,但需要你手写规则文件。它跟前端里 nginx 的 location / deny 配置更接近。
✅ PF 能做什么

按 IP/端口/协议过滤、NAT、端口转发、限速、地址集合(table)、按接口区分策略

🔍 与 Application Firewall 区别

系统设置里的“防火墙”是应用层 (ALF),只按应用签名判定;PF 是包层,基于五元组匹配。

2系统架构与关键文件

路径作用
/etc/pf.conf系统主配置文件(默认几乎为空,通过 anchor 加载子规则)
/etc/pf.anchors/系统/自定义 anchor 规则目录
/System/Library/LaunchDaemons/com.apple.pfctl.plist开机加载 PF 的 launchd 服务
/var/log/pf.log日志文件(需 pflog0 接口)
/dev/pfPF 与用户态通信的字符设备
💡 提示
macOS 上 PF 默认是启用状态但规则集为空,所以“感觉不到”。要用它,你只需写规则并加载即可,不用装任何东西。

3pfctl 命令速览

pfctl 是操作 PF 的唯一命令行工具,所有操作都需要 sudo。

# 启用 / 禁用 PF
sudo pfctl -e          # enable
sudo pfctl -d          # disable

# 加载规则文件(不启动)
sudo pfctl -f /etc/pf.conf

# 语法检查(不加载,推荐先跑一遍)
sudo pfctl -nf /etc/pf.conf

# 清空规则
sudo pfctl -F all
# 查看当前规则
sudo pfctl -sr

# 查看状态表(当前连接)
sudo pfctl -ss

# 查看统计信息
sudo pfctl -si
# 查看所有信息
sudo pfctl -sa

# 查看 anchors 列表
sudo pfctl -sA

# 查看某个 anchor 里的规则
sudo pfctl -a com.myrules -sr

# 动态操作 table
sudo pfctl -t badguys -T add 1.2.3.4
sudo pfctl -t badguys -T show
sudo pfctl -t badguys -T delete 1.2.3.4
前端类比 把 pfctl 想成 npm: -f 像 install(加载配置)、 -e/-d 像 run start/stop、 -s 像 ls(查看当前状态)。

4规则语法

PF 规则文件按顺序执行,但采用“最后匹配优先”(last match wins),除非规则里加了 quick。

规则的基本骨架

action  direction  [log]  [quick]  on interface  proto  from src  to dst  [flags/keep state]
字段可选值示例
actionpass / block / matchblock
directionin / outin
interface网卡名on en0
prototcp / udp / icmpproto tcp
from/to地址 + 端口from any to any port 22
状态keep state(默认)—
⚠️ 匹配顺序要点
默认“最后匹配的规则生效”。把最宽松的规则写在前面、越具体的写在越后面,或者用 quick 立即命中并结束匹配 — 这是最容易踩坑的地方。

5常用配置示例

示例 1:阻止所有入站,允许所有出站

# /etc/pf.anchors/com.mycompany
block in all
pass  out all keep state
pass  quick on lo0 all         # 放行本地回环

示例 2:仅允许特定 IP 访问 SSH (22 端口)

block in proto tcp to any port 22
pass  in quick proto tcp from 192.168.1.0/24 to any port 22 keep state

示例 3:封禁一批 IP(使用 table)

table <badguys> persist { 10.0.0.5, 203.0.113.0/24 }
block in quick from <badguys> to any

之后可以用命令动态增删:

sudo pfctl -t badguys -T add 1.2.3.4
sudo pfctl -t badguys -T show
sudo pfctl -t badguys -T delete 1.2.3.4
前端类比 table 就像一个响应式的 ref<Set>:引用它的规则不用改,你在运行时动态增删表项即可 — 无需 reload 规则。

示例 4:开发端口只对内网开放

block in quick proto tcp to any port { 3000, 5173, 8080 }
pass  in quick proto tcp from 192.168.0.0/16 to any port { 3000, 5173, 8080 }

示例 5:限速(带宽整形)

# 需要 ALTQ 支持,macOS 上此功能受限,仅供参考
pass out on en0 proto tcp to any port 443 queue web

6Anchor 机制(推荐使用)

Anchor 相当于“命名的规则子集”,可以被主配置动态加载。macOS 系统自己就通过 anchor 挂载了很多规则(比如 com.apple/*),所以推荐你也用 anchor 来放自己的规则,避免污染主 pf.conf。

前端类比 Anchor 就是 Vue 里的异步组件 / 子模块:主配置只写“挂载点”,具体规则放在独立文件里,可以按需加载、独立维护。

步骤:添加自己的 anchor

① 建立规则文件 /etc/pf.anchors/com.myrules:

block drop in quick from <banned> to any
table <banned> persist

② 修改 /etc/pf.conf,追加两行:

anchor "com.myrules"
load anchor "com.myrules" from "/etc/pf.anchors/com.myrules"

③ 加载并启用:

sudo pfctl -f /etc/pf.conf
sudo pfctl -e

7开机自动加载

PF 服务由 launchd 管理,默认已注册但规则为空。要让自定义规则开机生效,创建一个 launchd plist:

/Library/LaunchDaemons/com.myrules.pf.plist:

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>com.myrules.pf</string>
  <key>ProgramArguments</key>
  <array>
    <string>/sbin/pfctl</string>
    <string>-Ef</string>
    <string>/etc/pf.conf</string>
  </array>
  <key>RunAtLoad</key><true/>
</dict>
</plist>

加载服务:

sudo chown root:wheel /Library/LaunchDaemons/com.myrules.pf.plist
sudo launchctl load /Library/LaunchDaemons/com.myrules.pf.plist

8调试与排查

启用日志

在规则里加 log 关键字,匹配的包会被写到伪接口 pflog0:

block log quick from <banned> to any

实时查看日志:

sudo tcpdump -n -e -ttt -i pflog0

常用诊断命令

命令用途
sudo pfctl -sr列出当前规则
sudo pfctl -ss列出当前 state (连接)
sudo pfctl -si看统计:匹配数、丢弃数
sudo pfctl -sa看所有信息(all)
sudo pfctl -sA看 anchors 列表
sudo pfctl -a com.myrules -sr看某个 anchor 里的规则

9常见坑

🚫 别忘了放行 lo0
如果你写了 block in all 而没放行环回接口,本机很多服务(如 localhost 上的开发服务)会直接不通。永远加一条 pass quick on lo0 all。
⚠️ Last match wins
规则默认按“最后匹配生效”,不是“第一条命中”。想立即生效必须加 quick。这跟 iptables / 前端 if-else 的直觉不同。
⚠️ 修改 /etc/pf.conf 可能被系统覆盖
macOS 升级时系统文件可能被重置。推荐做法是:自定义规则放到 /etc/pf.anchors/,主 pf.conf 只加一行 anchor 挂载,或者干脆用独立的 launchd + 独立 conf 文件。
💡 SIP 与权限
即使有 sudo,某些系统级 anchor(如 com.apple/*)也不允许修改。这是 macOS 安全策略,别硬刚。
💡 与 Application Firewall / Little Snitch 关系
PF 位于最底层(内核网络栈),Application Firewall 在应用层,Little Snitch 通过 Network Extension 挂钩。它们互不冲突,但排查网络问题时要意识到"每层都可能拦"。
